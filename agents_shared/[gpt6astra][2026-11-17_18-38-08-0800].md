## 发现（按修复价值排序）

### F1 · P2 — SIGTERM 会遗留 TD 子进程

位置：[td/run_td.py](../td/run_td.py)，`run()` 的进程等待／清理（约 100–114 行）及缺失的 SIGTERM 处理。

`BaseException` 清理可以覆盖 Ctrl-C 引发的异常，但默认 SIGTERM 会直接结束 Python 包装器，不进入这一清理分支。隔离复现使用普通假子进程替代 TD：发送 SIGTERM 后包装器返回 `-15`，假 TD 子进程仍然存活；复现结束后已显式清理该自有进程。真实情况下，用户终止任务后可能继续渲染、占用 CPU/GPU，attempt 也可能留在 `rendering`。

建议：为取消和退出建立统一的 `finally`／信号清理路径，仅结束本次启动的进程；有界等待、必要时 kill，并对本次实际拥有的未完成 attempt 写入取消／失败状态。回归测试应启动受控假进程后发 SIGTERM，验证无遗留进程、正确退出码和状态；不能只测试 mock 回调。

### F2 · P2 — 超时并不总是有限

位置：[td/run_td.py](../td/run_td.py) 的 `--timeout`（约 130 行）和 `toeexpand`／`toecollapse` 调用（约 67、79 行）；[td_runner.py](../td/controller/td_runner.py) 的 deadline（约 92 行）。

参数接受 `nan`、`inf`、零和负数。隔离 mock 证实这些值都能穿过解析进入 `run()`；非有限值会破坏预期的有限 deadline。bootstrap 的两个外部子命令没有自己的 timeout，因此它们也不受后续 TD 等待上限保护。

建议：在创建文件／启动子进程前拒绝非有限和非正值，并给整个请求一个明确上限；bootstrap、进程探测和其他外部命令使用有界超时。TD 端读取请求时也验证 deadline。测试应证明非法值不启动任何工作，以及 bootstrap 超时不会遗留进程或半成品。

### F3 · P2 — 非零 TD 退出码仍可报告成功

位置：[td/run_td.py](../td/run_td.py) 的最终返回（约 180 行），以及 [td_runner.py](../td/controller/td_runner.py) 的 `finish()`。

TD 先写 `ok=true` 的结果，再延迟调用退出。包装器只依赖 `result.ok`，没有同时要求子进程正常退出。隔离 mock 返回 `({"ok": true, "exit_code": -11}, -11)` 时，`main()` 仍返回 0。因此退出阶段崩溃可能被上层 agent 当作成功。

建议：成功必须同时满足结果有效、请求成功、子进程退出码为 0；对非零退出保留结果供诊断，但返回失败。加入“先写成功结果、随后异常退出”的回归测试。

### F4 · P2 — 色彩重声明没有绑定已验证的运行配置

位置：[export_controller.py](../td/controller/export_controller.py) 的 `check()`、`_save_frame()`（约 130 行）和 `TDAdapter.png_color_redeclare`（约 190 行）。

修正是无条件类配置，前置检查没有核对 TD build、实际嵌入 shader／输出配置或匹配的校准记录。当前 guard 只判断 PNG 的标签是否等于已知常量。相同标签不能证明样本仍是 BT.709-OETF。

微型临时复现中，适配器报告 build `2099.99999`，输出刻意构造的线性 RGB 灰色样本并附带相同标签；前置检查为空、导出 `complete`、序列验证通过，记录却仍称 `chart-verified BT.709`。这说明文档中“新 build／模板必须重新验证，guard 强制保证”的表述不成立。该复现没有使用真实 TD，也不否定本次已验证配置的素材。

建议：把修正绑定到明确的 TD build、模板／实际 shader 和相关输出配置；变更后要求匹配的新校准证据。将校准身份和结果写入产物记录，避免只检查 job 的名称／版本或磁盘路径。回归测试覆盖未知 build、修改 shader／输出、相同标签但不同样本契约，以及已校准配置的成功路径。

### F5 · 文档边界 — 不保证自动避开播放测量

[td/run_td.py](../td/run_td.py) 和 [TD 指南](../td/README.md) 称拒绝已有 TD 进程就能保证不会与播放测量重叠。实际仅调用 `pgrep -x TouchDesigner`，没有与 `WallpaperProbe`／测量 harness 协调。

应去掉这一自动保证，保留人工分时要求；若要强制串行，需由 runner 和测量 harness 共同遵守的协调机制。Claude 此前确实没有同时测量的记录可以保留，但一次正确操作不能证明代码已实现互斥。
