## 修复与决定

| 问题 | 本轮处置 |
| --- | --- |
| F1：SIGTERM 遗留 TD | 统一 SIGINT/SIGTERM/异常清理路径，只处理本次持有的 `Popen` 子进程；先 terminate，5 秒后必要时 kill，再有界等待。TD 接受前置条件后写入请求 token 和 attempt 快照，host 仅将匹配且仍在 rendering 的任务标记失败。拒绝的任务、终态、外部已推进状态保持不变。 |
| F2：不受控超时 | 在任何子进程或文件创建前拒绝非有限、非正和超过 3600 秒的 timeout。共享 host deadline 覆盖进程探测、bootstrap、启动、渲染和退出；bootstrap helper 另有 30 秒上限。TD 端也验证 timeout。清理最多另加 10 秒／自有子进程。 |
| F3：异常退出假成功 | 结果必须匹配本次 action/token，`ok` 必须为布尔真，errors 必须为空，TD 退出码必须为 0。先写成功、退出时崩溃也判失败；CLI 返回非零。 |
| F4：无校准身份保护 | 新增固定校准 profile 和保留色卡证据，核对 TD build、磁盘模板／shader、实时嵌入 shader、uniform 绑定、节点类型／接线／锁定状态、格式、色彩设置、分辨率和 cook delay。开始前、每次保存前、写报告前都检查；未知或变化的配置拒绝。报告记录 profile/evidence 哈希及实际身份。 |
| F5：测量互斥过度承诺 | 明确 `pgrep` 仅检查当前 TD 进程，不检测播放器测量，也不是并发启动锁。渲染、编码与受控播放测量仍须分时进行。 |

代码：`td/run_td.py`、`td/controller/td_runner.py`、`td/controller/export_controller.py`；新增 `td/calibration/` 和 runner/calibration 测试，扩展 controller 测试。更新 TD 指南、计划的过时状态和共享交接状态。

校准范围有意限定为 **TD 2025.33230、soft_gradient v1、1280×720 RGBA8、当前已验证输出配置**。保留的两个 PNG 是之前真实运行的原始文件，共约 10.8 KB，不是伪造或本轮重生成的证据。新模板／build 应先采集原始样本并审阅校准，再进入生产导出；没有跳过校验的开关。详见[校准说明](../td/calibration/README.md)。

## 限制与下一步

F1–F5 在上述范围内关闭。未知 TD build／模板／分辨率不会自动继承此次校准；SIGKILL、断电无法执行清理；当前启动检查不是跨进程互斥锁。没有重新运行 bootstrap 重建或所有新 build 的校准。渲染耗时是普通回归记录，不是受控性能基准。

这仍不是最终 Mac 应用交付。本轮未做实际 AVPlayer 色彩／多轮循环观察、整机 CPU/GPU／内存验收、锁屏／睡眠试验；也未实现 agent API、天气连接器或实时 renderer。接下来完成 M1/M2 的受控资源与生命周期证据、播放方案决策，再推进 M4 最小应用。默认视频播放不依赖 TD 的产品要求不变。
