## Decisions

- **Frame naming is 0-based.** `frame_%06d.png`, so file `i` is phase `i/N` with no duplicated endpoint. This differs from the 1-based example in `research/03`.
- **Attempts and publication.** Each run gets a new `attempts/<id>/` directory and never reuses one. "Reject an existing output directory" is enforced per attempt, so the job's `output_dir` can hold repeat runs, as the repeatability check requires. Only `finalize` publishes: it assembles `bundle.partial/` and renames it to `bundles/<id>/` on the same filesystem, then sets state `complete`.
- **One color contract.** The only accepted contract is `rgb_rec709_bt709trc_full`; anything else is rejected. The TD shader produces it by encoding with the BT.709 OETF itself. A chart job checks that TD stores the 8-bit values unchanged. No sRGB/linear path was invented.
- **Reproducible encodes.** Encodes use `-map_metadata -1 -fflags +bitexact`, so the same frames give a byte-identical MP4 on the same build.
- **Validation added beyond the prompt:**
  - Color round trip: decoded RGB vs source PNG under the contract's matrix.
  - Loop-seam test.
  - `verify-index`: a frame-index strip in debug renders. A uniform one-frame cook delay still passes the seam check; this catches it, and it also reports image orientation.
- **TD controller design.** All TD API calls sit in `TDAdapter`, and the logic is tested with a fake adapter. It saves frames 2 TD frames after setting the frame index; this delay is a conservative default, to be validated with `verify-index`. Above 1280 px it refuses unless the license type is known and not Non-Commercial.
