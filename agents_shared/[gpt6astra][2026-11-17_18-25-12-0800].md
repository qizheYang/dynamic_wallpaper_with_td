# Agent/API platform scope and export/runtime boundaries

## User decisions and checkpoint

The user expanded the product to support their own agent API inside the Mac app, let agents read the skill and create wallpapers, open editable TD templates for manual creation, add custom API-driven effects, and work toward Wallpaper Engine's feature set. The concrete example was Los Angeles weather affecting appearance. The user explicitly chose **feature equivalence first, Steam Workshop compatibility evaluated separately**, then asked whether output can be video and what TouchEngine costs.

This is a researched scope/design checkpoint. It does not implement the Mac app, a model provider, a connector, `.env` loading, or a live renderer. Existing M1/M3 work remains useful and its measured limits are unchanged.

## Decisions and artifacts

- Preserve video as the first low-complexity export/playback path: MP4, static cover and metadata, with editable TD source retained separately. Weather can select among authored clips without reopening TD. A video does not itself query an API or preserve arbitrary continuous interaction.
- Separate the on-demand agent coordinator/provider from the data broker and visual renderer. Ordinary weather refresh changes validated fields/properties or clip selection; it does not call a model or regenerate a video.
- Plan live alternatives explicitly: constrained native scene, managed Web, optional embedded TouchEngine, and external TD live bridge. They have different dependencies and resource budgets. Do not promise arbitrary TD-network-to-native-app compilation.
- Keep provider and data credentials in app-owned connection profiles/Keychain; local `.env` is a selected development input, never exported or sent wholesale to the agent. Public examples contain empty key fields. New app/data manifests remain separate from the current strict video job schema.
- Expand M7–M10 for app-hosted generation/templates, weather/properties, live effects and broader feature coverage. Third-party player reuse can inform components/first playback, but cannot by itself provide the expanded product.

## Verified upstream facts and cost

Read official Wallpaper Engine/Steam, Derivative, Apple, Anthropic and Open-Meteo documentation; links attach to individual claims in the research. Two independent research agents checked WE capability coverage and TD runtime/export constraints. No candidate apps, SDKs or TD sessions were launched for this scope work.

TouchEngine has a documented macOS SDK and can load `.tox` in a host without the editor UI, but requires an installed TD/TouchPlayer runtime and appropriate paid end-user license. SDK integration has no licensing fee/royalty. On 2026-11-17 ordinary Commercial prices were **US$300 for TouchPlayer** and **US$600 for TouchDesigner**, with perpetual licenses and one year of included updates. An existing suitable license can satisfy the runtime requirement; free Non-Commercial does not unlock external TouchEngine hosting. No purchase, commercial-use entitlement or redistribution permission was assumed. Sources: [TouchEngine](https://derivative.ca/UserGuide/TouchEngine), [Commercial product page](https://derivative.ca/product/touchdesigner-commercial/34).

Playback of exported MP4 through the native video host has no TD runtime-license requirement. Authoring still needs a license appropriate to its use. This supports an optional TouchEngine mode rather than imposing its per-user dependency on ordinary playback.
