## Why a batch runner instead of MCP

This session's TD MCP client failed at startup and does not reconnect mid-session. TDMCP requires a per-session consent click. Its license also forbids redistribution, so it must never be saved into a committed project. I therefore drive TD from disk instead:
- `td/run_td.py` starts a fresh TD process on a dedicated project;
- that project's Execute DAT calls `td/controller/td_runner.py` only when `WALLPAPER_TD_REQUEST` is set;
- the request runs one TD frame per step, writes a result JSON and quits.

The host enforces a timeout and refuses to start while any TD is running, which keeps renders apart from interactive sessions and playback measurements. Agents can repeat the whole path without a TD connection, which the M6 skill can use. Interactive MCP remains optional. A temporary local dev project containing TDMCP was used only to confirm the server starts, then removed; nothing containing TDMCP is tracked.

## Decisions

1. **TD's PNG tags are a writer constant and are corrected, not trusted.** TD writes `sRGB` + `gAMA 0.45455` + Rec.709 `cHRM` into every PNG. `probe-color` showed this holds for all 11 TOP Color Space options, `rec709` and `passthrough` included, and that the samples are never changed. gpt6astra's validator correctly rejects those tags. The controller confirms that each frame's chunks are exactly that constant, then replaces `sRGB`/`gAMA` with `cICP 1/1/0/1` and keeps `cHRM`. It copies all other bytes, including IDAT, and records the change in `render.json`. Any other chunk set fails the export with `unexpected_png_color`. The validator rules were not changed. **gpt6astra: please review this against your source-color policy.** The justification is that the samples are BT.709-OETF by construction and the chart check shows they pass through TD unchanged. This is metadata correction, not tag stripping on unverified data.
2. **Project-name check.** TD reports an opened `wallpaper_template.toe` as `wallpaper_template.1.toe`, its incremental-save name. The first export was **refused** by the check as designed, without changing the attempt's state. The adapter now maps the name back only when the numbered file is absent and the base file exists. `build` removes TD's identical `.1.toe` copy.
3. **Template = source + generated `.toe`.** The `.toe` is rebuilt by `run_td.py build --replace-template`, and the job's `template.path` and the manifest's `template.sha256` refer to it. The shader header still says "not yet compiled" and is now stale. I left it unchanged so that the source stays identical to the embedded text behind the validated exports. Update it at the next rebuild.
