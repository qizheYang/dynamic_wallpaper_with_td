## 本轮交付目标

实现一个可重复的最小闭环：版本化 job → 小型周期 TD 模板 → 精确 PNG 序列 → 编码/校验 → 视频、静态封面与 manifest。第一份真实任务固定为：**1280×720、24 fps、480 帧、20 秒、seed=42**。画面采用慢速、柔和的抽象渐变或几何形状，不引入有历史状态的粒子/反馈模拟。

按以下顺序推进，优先把可验证的逻辑写在磁盘上：

1. 建立清晰的小目录，例如 `pipeline/`、`jobs/`、`td/`、`tests/`；优先 Python 标准库，新增依赖须有具体必要性。定义并验证 job/schema：版本、job_id、模板、seed、尺寸、FPS、帧数、参数、源色彩契约、输出目录。拒绝无效尺寸/帧率/帧数、不支持的色彩契约和已有输出目录。
2. 实现序列验证、FFmpeg 编码、ffprobe/完整解码验证、封面和 manifest。使用参数数组调用子进程，保存可复现命令；失败、取消或残缺帧不能生成成功标志。每次尝试用新目录，全部验证完成后才发布最终文件和 `complete` 状态。
3. 用极小的合成图片测试磁盘管线，覆盖成功、漏帧、编号缺口、损坏/尺寸不一致、编码失败、取消、未知色彩和重复输出等实质性失败路径。合成输入的成功不算 TD 导出完成。
4. 重新检查 TD MCP 是否可用、当前工程路径、build 和许可证类型。读取能力/类型即可，不读取或记录许可证密钥。只在该项目专用的 `.toe` 中工作；如果 TD 正开着无关或未保存工程，不覆盖、不修改它。先完成独立磁盘代码，再明确请求用户打开专用工程；若当前状态允许安全新建，可在 `td/` 创建专用工程。
5. 按可用 TD skills 工作：先 `td-general` 和构建规划，查询实际 operator/API 参数，做一个小网络，逐步验证 errors/values，最后整理布局。模板的动画完全由 `i/N` 驱动（`i=0…479`），不采样重复终点，不依赖墙钟或 `absTime`。固定种子；控制器逐帧让出事件循环，确认写入完成后再推进，任务之间复位状态。
6. 保存模板及外部源码，执行一次真实 TD 导出，再重复同一任务验证可重复性。比较源帧内容/哈希，并记录允许的差异来源；不把编码文件哈希一致当作跨平台保证。检查末帧→首帧与普通相邻帧差异，并观察多轮播放；首尾帧不必完全相同。

## 色彩是交付条件

更新后的 FFmpeg 示例只适用于 **full-range RGB、Rec.709 primaries、且数值已经按 BT.709 transfer 编码** 的输入。`scale` 指定矩阵/范围，`setparams` 仅标记属性；它们不能自动把线性或 sRGB transfer 转成 BT.709。

先确认 TD 实际输出契约；若不同，明确实现并测试对应转换，不要简单补标签。校验 H.264 / `yuv420p` / 24 fps / 480 个解码帧 / 20 秒 / 无音频，以及 `color_space`、`color_primaries`、`color_transfer`、`color_range`。使用色卡验证像素，再在 TD 与 AVPlayerLayer 对照视觉；如果该视觉检查暂不可执行，保留候选产物并明确该验收未完成，不宣布最终艺术素材通过。
